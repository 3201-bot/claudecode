# e-STOCKER 下書き量産手順

e-STOCKER(https://e-stocker.com)はeBay出品管理ツール。「ダイレクト出品」(scan-listing)ページで、仕入元URLから出品下書きを作る。ブラウザ操作はChrome拡張(Claude in Chrome)接続のセッションで行う。

前提: ユーザーがe-STOCKERにログイン済みであること。ログイン画面が出たらユーザーに操作を依頼して待つ。

## 1件の手順

1. `scan-listing` ページを開く(1件ごとに新規で開く)
2. 仕入先URLを入力 →「読み込み」ボタンを**実クリック** → 「商品情報を取得しました」モーダルの「確認」を**実クリック**(この2つはJSクリックでは発火しない)
3. SKU・英語タイトル(80字以内)を入力。説明は `references/description-template.md` のHTML骨格で生成してエディタに流し込む(プレーンテキスト禁止。ユーザー独自テンプレートが登録済みならそちらを優先)
4. カテゴリ検索: カテゴリ名をtype → **候補にIDが表示される行**をクリック(例: Wristwatches(31387)、Video Game Consoles(139971))
   - 罠: typeしても候補がフィルタされず全カテゴリのアルファベット順が出ることがある → **全選択→Backspace→再type**で再フィルタ
5. 状態(Condition)を選択。動作確認済みの中古=Used/Pre-owned Good系。ジャンク・訳あり=Fair系またはFor parts(**状態の開示はタイトル・説明文にも入れる**。商品状態のテキストエリアは永続しないことがあるため、開示は説明HTML側に必ず含める)
6. ブランド欄に正しいブランドを入力
7. **アイテムスペック**: 埋まっているほどeBayの検索絞り込みと露出に効く。**Model 1行で済ませない。**
   - **最速の方法**: ベンチマーク(同型番のeBay出品)のItem IDがあれば「eBay商品から取得」ボタンで一括投入する
   - **取得したら全行を実物と照合する(省略禁止)**: 取得スペックは「他人の商品の属性」なので、色・世代・付属品違いがそのまま流入する。実物と違う行は修正。保証系の行(Manufacturer/Seller Warranty, Service Records等)は削除。型番系の行はカラー等未確定の情報を含むなら型番のみに安全化
   - 取得ボタンを使わない場合は、推奨スペックのドロップダウンから行を追加して主要項目を埋める(時計の例: Department/Movement/Model/Display/Case Color/Band Material/Water Resistance の7項目。カメラ・ゲーム機も同様にカテゴリの必須+主要項目を揃える)。カスタム項目行は下書きで永続しないため使わない
   - **前商品の値の残留に注意**: 量産中、前の商品のブランドやスペックがフォームに残ることがある。「値が入っていたらスキップ」というガードは残留値を温存する事故になるため、**毎回ガードなしで全項目を明示上書き**する(実事故: Nintendo商品にSonyが残留した)
8. 価格・数量1・欠品時=自動取り下げ・ベストオファー設定
   - **プロモーションリスティング: ON+入札率2.1%がデフォルト**(ユーザーのCLAUDE.mdに別の率が記録されていればそちらを優先)。チェックボックスは**実クリック**が必要
   - ユーザーが「広告は3%にして」等と言ったら、その場で適用し、CLAUDE.mdのデフォルト率も更新する
   - プロモーションのチェックボックスは**実クリック**が必要
9. 配送=命名済みシッピングポリシー / 支払・返品ポリシー / 発送元=Japan
   - eBay側でポリシーを新規作成・変更した直後は、プルダウンに反映されないことがある → ビジネスポリシー欄の**「ポリシー更新」ボタン**を押して同期する(e-STOCKER側のキャッシュ更新)
10. 「下書き保存」→ ダイアログに下書き名を入力 →「保存」

## 保存の検収(必須・省略禁止)

- **保存の前に重複を確認する。** 下書き一覧・出品リストに同一の仕入元URL・SKU・同一型番+同一状態の商品が既にないか(ゲート⓪をすり抜けた場合の最終防波堤)
- **「ダイアログが閉じた=保存成功」と判定しない。** 実事故: この判定で9件連続「保存成功」と報告し、実際は7件が存在しなかった(ボタンのクリックが空振りしていた)
- 保存のたびに `/drafts`(保存データ呼び出し)を再読込し、**行が実際に増えたことを数えてから**完了報告する
- 繰り返し操作ではDOM参照を毎回取り直す。前の参照を使い回さない
- 初回の1件は、保存後に下書きを開き直してスペック・ブランドの実値が永続しているかを確認してから量産に入る

## 連続入力の罠

- 価格欄など連続フィールド入力は、2つ目の入力が画面の再描画で消えることがある → 入力の間に1秒待ち、入力後に値を目視確認してから保存
- フォーム作業は**全項目の決定表**を先に作る。「デフォルトのまま」も明示的な決定として書く(触らなかった項目は検証されないバイアスがある)

## 説明文HTMLの原則

- タイトル・状態・説明は**仕入元の実物ページから生成**する。他セラーの出品のコピーは禁止(規約違反+状態不一致事故の温床)
- ジャンク・訳あり品は、症状(電池切れ/動作未確認/傷)を英文で明記した CONDITION NOTES を説明冒頭に置く
- 過大表記の禁止: 仕入元が「傷あり」なら Excellent と書かない。無申告・過大表記はバイヤー勝訴のクレーム(INAD)に直結する

## 出品後(権限がある場合)・ユーザーが出品した後

1. itemIDの回収は1行ずつやらない。**SKU照合による一括回収**を行う(手順は `references/ledger.md` §2)。下書き時の台帳記帳は同 §1
2. **在庫監視の確認**: 出品一覧で、仕入元売切れ時の自動取り下げ(在庫キーワード)が**全件に効いているか**を横串で確認する
   - 実事故: 仕入元サイトによってツールの監視設定が入ったり入らなかったりする実装差があり、3日分22件・約$9,860分が監視ゼロで公開されていた。表面上は何も壊れて見えない
   - 新しい仕入元サイトを使い始めた初回は必ずこの横串確認を行う。監視キーワードは推測せず、生きているページと終了ページのHTML差分から決める
3. 報告: 件数・SKU一覧・台帳更新の内容・(却下があれば)却下理由
