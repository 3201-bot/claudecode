# 台帳への記帳 — 下書き時の記入と、出品後のitemID一括回収

ユーザーが教材同梱の「eBay出品台帳テンプレート」(Googleスプレッドシート)を使っている場合の記帳手順。テンプレートを使っていない場合は、ローカルの台帳.csvに同じ項目を記録する。

## 台帳の構造(前提)

- タブ名「台帳」。ヘッダーは4行目、データは5行目から
- **入力列は B〜F と J〜U の2ブロックだけ**:
  - B日付 / C SKU / D状態 / Eタイトル / F販売価格$
  - J仕入価格¥ / K割引¥ / L重量g / M発送方法 / N地帯 / O CategoryID / P関税% / Q広告% / R確定レート / S仕入元URL / T eBay itemID / U備考
- **数式列に書き込むことは絶対禁止**: A(No)・G〜I(利益・損益分岐)・V列以降(手数料内訳・eBay URL自動生成)。ここに貼ると台帳が壊れる
- T(itemID)は数字のみ。URLは書かない(AL列がitemIDから自動生成する)

## 1. 下書き保存後の記帳

e-STOCKERの下書き保存を確認したら、その内容を台帳に1行記帳する。

**標準ルート(最優先): 「記帳受付」タブ経由。** 台帳スプレッドシートには記帳受付タブが同梱されている(無ければシートを開き直すと自動生成される)。書き込みはセルへの直接編集ではなく、このタブの空セルに**1行のJSON**を打ち込んでEnterするだけでよい:

```
{"to":"台帳","rows":[["日付","SKU","状態","タイトル",販売価格$,仕入価格¥,割引¥,重量g,"発送方法","地帯",CategoryID,関税%,広告%,"確定レート","仕入元URL","itemID","備考"]]}
```

(17列=B〜F+J〜U。ボード記帳は `{"to":"お手本帳",...}` / `{"to":"仕入先帳",...}` で8列)。

**既存行の更新**(出品後のitemID反映・状態変更・売却時の確定レート)も同じタブで行う。SKUを鍵に行を特定する:

```
{"op":"update","rows":[{"key":"GM-260726-01-M7380","set":{"D":"出品中","T":"257613999999"}}]}
```

更新できるのは D状態/Eタイトル/F販売価格$/P関税%/Q広告%/R確定レート/S仕入元URL/T itemID/U備考 のみ(数式列は構造上更新できない=壊せない)。売却時は `{"set":{"D":"売れた","R":152.3}}`。書き込み後、記帳受付タブのB1に「✓ ◯行を記帳」が出る。**必ずB1の結果を読み、さらにgvizで対象タブの行が増えたことを確認してから完了報告する。** クリックも貼り付けも不要なので、ブラウザ操作が不安定な環境でも安定して通る。

以下の直接編集は、記帳受付タブが存在しない旧版シートのためのフォールバック。**注意: セルへの直接タイプは先頭の日本語文字が欠落することがある**(IME合成の癖。実測で「見送り」→「送り」等)。直接タイプするときは値を英数字から始めるか、貼り付けを使う。JSONは「{」始まりなのでこの問題が起きない——記帳受付ルートが標準である理由のひとつ:

1. 台帳タブを開き、最下データ行の次の空行番号を特定する
2. **セル移動は必ず名前ボックスで行う**(グリッドのクリックは座標ズレでヘッダーを壊した実事故がある)。B{行}を指定し、1ブロック目(日付/SKU/状態=下書き/タイトル/販売価格$)をタブ区切りで貼る
3. J{行}を指定し、2ブロック目(仕入実価格/割引/重量g/発送方法/地帯/CategoryID/関税%/広告%/空/仕入元URL/空/備考)を貼る。**Tは空のまま**(itemIDはまだこの世に存在しない)
4. 検収: 貼り付け後に行が実際に増え、G列(利益額)が計算されていることを確認してから完了報告する。「貼った」ではなく「増えて計算された」を確認する
5. 途中でヘッダー行(4行目)や数式列を上書きしていないか目視。壊した場合は直ちに復旧してから続行

ブラウザが固まった/貼り付けが不安定な場合のフォールバック: 2ブロックのタブ区切りテキストをそのまま出力し、「B{行}とJ{行}に貼ってください」とユーザーに渡す。

## 2. 出品後のitemID一括回収(SKU照合)

ユーザーが出品ボタンを押した後、「出品済みを台帳に反映して」と言われたら実行する。1行ずつのURLコピペはしない。**SKUを鍵にした一括照合**で行う。

1. eBay Seller Hubのアクティブ一覧(またはe-STOCKERの商品リスト)から、各出品の**カスタムラベル(=SKU)とitemID**のペアを収集する
2. 台帳の「itemIDが空欄」かつ「SKUが一致」する行に、**itemIDの数字だけ**を記入する(eBay URLはAL列が自動生成)
3. 状態の同期: 一覧に存在する行=「出品中」に更新。台帳が出品中なのに一覧に無い行=**勝手に変更せず**「要確認」としてユーザーに報告する(売切れ・取下げ・削除の判断は人間)
4. 報告: 更新した行数 / SKUとitemIDの対応一覧 / 要確認の一覧

## 3. 売れた後

ユーザーから売れた報告を受けたら: 状態=「売れた」に更新し、入金時の実レートを確定レート(R列)に記入する。確定レートが入ると、その行の利益計算は現在レートから切り離されて凍結される(無在庫の行は市場と一緒に呼吸し、売れた行は確定する設計)。
