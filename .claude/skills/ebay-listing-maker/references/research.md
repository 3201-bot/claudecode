# リサーチの3軸 — 予想せず、集計する

大原則: 根拠にしてよいのは**Sold(実際に売れた記録)だけ**。アクティブ出品の価格は「売れていない価格」かもしれない。「売れそう」という予想でリサーチしない。

## 0. リサーチ開始前の読み込み(重複ガード)

検索を始める前に、必ず以下を読み込んで**除外リスト**を作る:

1. **台帳**の仕入元URL列(S列)とSKU一覧 — 出品中・下書き済・売れた行の仕入元は再候補化しない
2. **セラーボード**(`references/seller-board.md`)— 最終調査日が新しいセラーの再調査はスキップ
3. 却下記録があれば却下済み候補も除外する

3軸は同じ商品に別ルートで到達しうる(キーワード検索とセラー丸ごとスキャンが同一品を拾う等)。この読み込みを飛ばすと、同じ候補の再提案や**同一商品の重複出品**(eBayの重複出品ポリシー違反)につながる。

## ぶん投げ標準ルート(曖昧な指示への対応)

「車パーツに強いセラーをヤフオクから探して」「◯◯系のジャンルを見といて」のような**曖昧な指示は歓迎する**。細かいキーワードをユーザーに要求せず、以下の標準ルートで動く:

1. 未知ジャンルなら、TerapeakでカテゴリをID単位まで特定する(カテゴリ検索→絞り込み)
2. そのカテゴリのSold・直近90日・日本発送で実売の型番・価格帯を集計する
3. 集計から軸2(お手本セラー)・軸3(仕入元)へ展開する
4. **結果は必ずセラーボードと台帳に着地させる**。チャットの返答だけで完結させない

指示が曖昧でも、基準(Soldのみ・実ページ確認・9割却下が正常)と成果物の形式は変えない。

## リサーチ地図 — 戦略の宣言と進捗の可視化

キーワードを思いつきで生成して黙々と検索するのは禁止。「なぜ今夜その検索なのか」を説明できない検索は、ユーザーから見ればクレジットの浪費と区別がつかない。ジャンル単位のリサーチは、必ず**地図**を作ってから始める。

### 地図の宣言(ジャンル開始時に1回)

1. ジャンルを**2〜3軸のマトリクス**に分解する(例: ブランド品=ブランド×アイテム種別、カメラ=メーカー×機種系統×動作状態、トレカ=シリーズ×年代×鑑定有無)。軸の粗さは**最初は粗く**。セル数の目安は30〜100
2. 作業フォルダに `リサーチ地図_<ジャンル>.md` として保存し、**検索を始める前にユーザーに提示する**。「この地図をこの順で埋めます」と宣言してから掘る
3. 各セルには実測だけを記録する: 状態(未踏/当たり/死に/深掘り中)・Sold密度・利益候補率・最終調査日
4. 高額・真贋リスク品(PSA/鑑定カード・ハイブランド等)のセルは、地図上に「要検討リスト行き」と明記して自動化ラインから外す(安全ルール5)

### 夜ごとの配分(当たりで掘り、実測で捨てる)

1晩の検索予算はデフォルト6検索。**当たりセルの深掘り4 : 未踏セルの探索2**で配分する。

- **深掘り**: 当たったセル(利益候補が出た/Sold密度が高い)は解像度を1段上げる(コーチ×バッグが当たった→ライン名・型番のセルに分割して掘る)
- **深掘りは「子地図」で行う(トップ地図は細分化しない)**: 当たりセル専用に `リサーチ地図_<ジャンル>_<セル名>.md` を新設する。トップ地図に型番列を足して巨大化させない(数千マスの死にカタログになり、配分判断の道具でなくなる)
  - 子地図の**行=型番**。ただし人間や図鑑の網羅ではなく、**TerapeakのSold集計に実際に出てきた型番だけ**を行にする(売れていない型番は行にすら載せない。市場が行を決める)
  - 子地図の**列=価格を割る軸**。同じ型番でもSold価格が大きく割れる要因を列にする(カメラなら動作状態×構成(ボディ/レンズ付)、トレカなら鑑定有無×状態、ブランド品ならライン×状態など)
  - 3層構造で運用する: **ジャンル地図(戦略・どのセルを掘るか) → 子地図(戦術・どの型番をいくらで狙うか) → 台帳(個体の実績)**。トップ地図のセルには子地図の有無だけ記す
- **撤退**: 2回掘ってゼロのセルは「死に」マークして以後掘らない。**死にセルも成果**。地図は埋めるものではなく、掘る価値のない場所を確定させるためのもの
- **語彙の補充は人間の承認制**: 探索中に見つけた新しい軸・キーワード(お手本セラーのSoldに出てきた未知の型番・シリーズ名等)は、勝手にプールへ足さず「地図への追加提案」として朝の報告に載せる。承認されたものだけ地図に入れる(無人で語彙が野放図に増えると検品ゲートに未知ジャンルが流れ込む)

なお、eBay Soldの90日窓は毎日1日ずつしか動かない。**同じセルを同じ解像度で連夜掘らない**(需要側の再訪は週1で十分)。毎晩やる価値があるのは、仕入元側の新着スキャンと在庫監視(供給は毎日入れ替わる)。

### 朝の報告(カバレッジ行を必須にする)

リサーチ報告の冒頭に、必ず地図の進捗を1〜2行で書く:

```
地図: ブランド品 84セル中31調査済み | 当たり7 | 死に11 | 今夜の新規2(フェンディ×ポーチ=当たり) | 追加提案1件
このペースなら未踏セル一周まであと約3週間。
```

これが無い報告は「何をやったか」しか伝えず、「どこまで来たか」が伝わらない。ユーザーが夜間リサーチを止める最大の理由は、進捗が見えないことである。

### 共有用出力(研究ラボ向け)

「地図を共有用に出力して」と言われたら、地図から**仕入元URL・SKU・実仕入価格・具体的な型番リストを伏せた**要約(セル×状態×当たり率のみのmarkdown表)を生成する。手の内を明かさずにセルの温度だけを共有するための形式。整形はAIの仕事にし、ユーザーには貼るだけの状態で渡す。

**巡回指示**: 「お手本を回して」=お手本帳の**チェック済み**セラーのSold再分析。「仕入先を回して」=仕入先帳の**チェック済み**仕入先の再スキャン。チェックの有無で対象を選ぶ(詳細は`seller-board.md`のチェック列ルール)。

## 軸1・商品起点(基本形)

1. Terapeak(eBay公式リサーチ)で、カテゴリ/キーワード検索 → **Sold・直近90日**に絞る
   - 検索URLでの日本所在フィルタ(`LH_LocatedIn=1&_salic=104`)は**効かないことがある**(2026-07-26実測: 英国・タイ等が混入)。フィルタ後も各結果の「発送元」表示を必ず目視し、日本発だけを採用する
2. **「日本から発送」で絞る** — 日本人セラーが実際に売った物=日本で仕入れられる物のリストになる
3. 売れた型番・仕様・落札価格・売れた頻度を表に記録
4. メルカリ/ヤフオクで同一型番・同等状態の出品を探す → 見つかった候補は検品ゲートへ

## 軸2・セラー起点(設計図を手に入れる)

1. Soldに繰り返し登場する優良日本人セラーを特定する(評価数の伸び・専門ジャンルの明確さ)。**特定したセラーはセラーボード(お手本帳)に記帳する**
   - **お手本の質は「仕入れ再現性」で測る**: 有在庫の専門店(独自仕入れルート持ち)は品揃えの参考にはなるが、写しても仕入元が見つからないことが多い。お手本として上位なのは、**そのSold商品が日本のマーケットプレイス(メルカリ/ヤフオク)で画像逆引きヒットするセラー**=同じ仕入れが自分にもできる相手。数件逆引きして、ヒット率をお手本帳のメモに書く(例:「逆引き3/5ヒット=無在庫型の可能性高」「0/5=有在庫専門店。品揃え参考のみ」)
2. そのセラーの直近90日Soldを分析: 型番・売値・頻度の表を作り、品揃えと価格の設計図にする
3. 応用: そのセラーのアクティブ出品をGoogleレンズ等で画像検索すると、日本の仕入元まで逆引きできることがある。同じ仕入元から同等品を仕入れ、5%下げてリストする戦い方まで可能
4. **出品数が多いセラーの優先抽出**: 何千品も扱うセラーは全件見ない。(a) e-STOCKERの「販売リサーチ」に販売者IDを入れ、**価格範囲(USD)で絞る**(並べ替えはBest Match/新着順/価格/終了間近のみ。ウォッチ数ソートは無い)。(b) 個別の商品ページに「X watchers」表示があれば読み取り、**ウォッチ数の多い商品を優先**する。表示が無いセラー・商品では無理にウォッチを追わず、カテゴリ知見と価格帯で選定にフォールバックする(実測: ウォッチャー数が表示されないセラーは実在する)

**線引き(必ず守る)**:
- セーフ: 品揃えの参考、価格の追随、Sold分析(公開情報の分析)
- アウト: **写真・説明文のコピー**。eBay規約違反(画像の無断使用)であり、かつ「他人の商品の状態を自分の実物に接着する」事故の温床。タイトル・状態・説明は必ず自分の仕入元の実物ページから生成する

## 軸3・仕入元起点(量を出す)

1. 軸1・2の調査中、候補商品の「この出品者の他の出品」を必ず確認する
2. 特定ジャンルを専門で・正確な状態記載で・継続的に出す国内出品者を「優良出品者」として**セラーボード(仕入先帳)に記帳する**
   - **記帳前に必ずセラーページ(出品一覧)を開いて実測する**: ①出品中の総数 ②対象ジャンルの件数。検索結果1ページの見た目や商品ページ1枚から「多数出品してそう」と推定で書かない(実事故: ストア形式から量産型と推定した3店のうち2店が、実際は出品0〜3件だった。オークション型ストアは出品が回転して空になる)。丸ごとスキャンに値する目安は**対象ジャンル30件以上**。実測した件数を仕入先帳のメモに記録する
   - **ストアか個人かは選定基準にしない**。基準は「評価が高い・状態記載が正確・安く仕入れられる」。個人の一点物は売り切れが早い前提で扱うが、それは在庫監視(自動取り下げ)が受け止めるリスクであり、候補から外す理由にはならない
3. 優良出品者の出品リストを丸ごと読み、検品ゲートに流す。1人見つければ数十品が一気に候補化する。スキャン後は仕入先帳のスキャン履歴を更新する(例: 7/20: 30件→生存4)

## 型番衝突の罠(全軸共通)

型番の文字列一致だけで同一商品と判定しない。実事故: 高級カセットデッキの型番検索で「◯◯**専用カバー**」(¥3,980)が本体(相場数十万円)と誤認され、高利益候補として報告された。

**除外ワード**: 型番直後の「専用/用/対応/向け」、「〜のみ」、「修理致します/承ります」、「修理部品/補修用/交換用」、「ジャンク」(※ジャンクは除外ではなく明記出品の対象だが、リサーチ段階では別トラックに分ける)。「修理済み」は良品シグナルなので除外しない。年式範囲(例: 2009-2014)は型番ではない。

**新しいカテゴリの初回は、検索結果をユーザーに目視検品してもらう。**

## SKU規約

SKUに「いつ・どこから・いくらの想定か」を刻む。形式例:
```
<カテゴリ略号>-<YYMMDD>-<連番>-M<仕入価格>-<ポリシー識別子>
例: WCH-260710-G01-M6980-F
```
- 末尾の識別子はシッピングポリシーの区分(例: F=FREE-DDP系、S=別建て送料系)。SKUを見ただけで仕入価格と配送設計が分かる
- M値(仕入価格)は**実ページで確認した実価格**のみ。Lens・検索結果・キャッシュの数字の転記は禁止
- 仕入元URLは台帳でSKUと紐づける
- 予備の仕入候補リンクがある場合、候補化と同時点で生存確認する(メルカリの一点物は数時間で消える前提。店舗系=再供給ありは生存率が高い)
