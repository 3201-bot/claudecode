# セラーボード — 「お手本帳」と「仕入先帳」の2タブ

リサーチの成果(セラー情報)をチャットに書き捨てず、台帳スプレッドシートの専用タブに蓄積する。
**このボードが、日をまたいだリサーチの記憶になる。** 調査済みのセラーを再調査しない・同じ仕入元を二重にスキャンしない判断は、すべてこのボードを根拠に行う。

## 運用原則(台帳と同じ思想)

- **AIが記入し、人間はチェック列だけ触る**
- 初期状態は**空**。ユーザーの運用から育てる(初期値のセラーリストは同梱しない)
- 配布テンプレートに2タブとも同梱済み(**1行目=説明文、2行目=ヘッダー、記帳は3行目以降**)。タブが無い場合のみ初回セットアップ時にAIが作成する(同じ行構成で)
- 記帳は**「記帳受付」タブへのJSON投入**で行う(`ledger.md`の標準ルート参照)。ブラウザでのセル直接編集はフォールバック

## タブ1: eBayセラーボード(お手本帳)

「何を売るか」を写させてもらう先生の名簿。軸2(セラー起点)の成果物置き場。

| 列 | 内容 |
|---|---|
| セラーID | eBayのセラー名 |
| ジャンル | 主な商材。**複数・混合は「フィルムカメラ+ゲーム」「雑多」のように実態どおり書く**(一語に無理にまとめない) |
| 評価数 | 調査時点のフィードバック数 |
| 直近90日Sold | Terapeakで確認した実売件数 |
| 主な価格帯 | 例: $80-300 |
| 最終調査日 | このセラーのSold分析を最後に行った日 |
| メモ | 強み・特徴(例: OM系に強い/送料無料型) |
| チェック | 人間用。お手本として採用するか(AIは書き込まない) |
| セラーページ(自動)/Sold一覧(自動) | **数式列。AIは書き込まない**。セラーIDからeBayのセラーページと日本発Sold一覧のリンクが自動生成される |

## タブ2: 仕入先ボード(仕入先帳)

「どこで買うか」の現場リスト。軸3(仕入元起点)の成果物置き場。

| 列 | 内容 |
|---|---|
| 仕入元ID/名 | 出品者名またはストア名 |
| サイト | ヤフオク/メルカリ/ラクマ/その他 |
| URL | 出品者ページ |
| ジャンル | 複数・「雑多」可(タブ1と同じ方針) |
| 状態記載の質 | 正確/普通/雑(検品ゲート③の通りやすさに直結) |
| スキャン履歴 | 例: 7/20: 30件→生存4(却下率87%) |
| 生存率 | 候補が売り切れる速さの体感(店舗系=高、一点物=低) |
| チェック | 人間用。継続仕入先として採用するか(AIは書き込まない) |

## チェック列の意味(AIの行動が変わる)

チェック列は**ユーザーの「採用」裁定**であり、AIの行動を次のように変える。AIは絶対にこの列へ書き込まない。

- **お手本帳のチェック済みセラー** = 定点観測の対象。「お手本を回して」等の指示や定期リサーチでは、**チェック済みの行だけ**を対象にSoldを再分析し、新しい売れ筋を拾う。未チェックのセラーは記録と提案までにとどめ、勝手に設計図として使い続けない
- **仕入先帳のチェック済み仕入先** = 再スキャンの標準対象。「仕入先を回して」では**チェック済みの行だけ**を順にスキャンする。未チェックは初回スキャン止まり
- チェックが外されたら、以後の自発的な巡回対象から外す(ユーザーが名指しした場合は別)

## いつ書くか

1. **軸2・軸3の調査でセラーを評価したら、その場で1行記帳**(採用・見送りに関わらず。見送り理由はメモへ)
2. **丸ごとスキャン(量産)を実行したら、スキャン履歴を更新**
3. リサーチ開始時にこのボードを読み、**最終調査日が新しいセラーの再調査はスキップ**(ユーザーが明示的に再調査を指示した場合を除く)

## ぶん投げ指示への対応

「◯◯系に強いセラーをヤフオクから探して」のような曖昧な指示は歓迎する。標準ルートは `research.md` の「ぶん投げ標準ルート」に従い、**結果は必ずこのボードに着地させる**。チャット本文だけで完結させない。
